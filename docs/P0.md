# P0 可行性验证

目标：在正式开发转发服务之前，确认整条技术路线中风险最大的几个点都走得通。

## 运行

```bash
docker compose up -d --build
```

打开 `http://服务器IP:8080`，密码为 `WEB_PASSWORD`（未设置时见 `data/.web_password`）。容器启动后，看门狗会自动拉起模拟器并常驻运行。

### 运行环境

| 项目 | 要求 |
| --- | --- |
| 架构 | x86_64 |
| KVM | 必须。容器需 `--device /dev/kvm` |
| 内存 | 宿主机建议 ≥ 8GB（模拟器默认 4GB，可在面板调整） |
| 磁盘 | 镜像约 6–8GB，数据约 8GB+ |

**Windows + Docker Desktop**：默认没有 `/dev/kvm`。需要满足两点：
- 使用 **WSL2 后端**（Windows 11 的 WSL2 默认开启嵌套虚拟化），并在 Docker Desktop → Settings → Resources 把内存调到 8GB 以上；
- 或者用 Hyper-V 后端，并给 Docker Desktop 的虚拟机开启嵌套虚拟化（不保证 Docker Desktop 重启后不会被重置）。

检查方法：`docker run --rm --device /dev/kvm alpine ls -l /dev/kvm`。Git Bash 里需要在命令前加 `MSYS_NO_PATHCONV=1`。

## 验证清单

面板「概览」页有同样的清单，能自动判断的项会自动打勾。

| # | 验证项 | 怎么做 | 不通过时的退路 |
| --- | --- | --- | --- |
| 1 | KVM 可用、模拟器能开机 | 看概览页「安卓模拟器」显示已开机 | 换支持 KVM 的宿主机 |
| 2 | 系统镜像带 ARM 转译 | 概览页「ARM 转译」：abilist 含 `arm64-v8a` | 构建时换 `ANDROID_API`（30–35）；或换 ARM 宿主机用 Redroid |
| 3 | 微信安装成功 | 「设备与微信」上传官方 APK，ABI 应为 `arm64-v8a` | 同上 |
| 4 | 微信登录成功 | 在「安卓画面」中登录。平板模式显示二维码，用真手机扫 | 平板识别失败：调整分辨率和 dpi，保证最小宽度 ≥ 600dp |
| 5 | 平板模式下真手机不被挤下线 | 登录后检查真手机上的微信 | 改用小号，以手机模式登录 |
| 6 | 连续 24 小时稳定 | 看「稳定性」统计里微信被重新拉起的次数，以及是否掉线 | 加大内存或核数、定时重启 |
| 7 | 数据库解密 | 「数据库验证」→ 运行解密验证 | IMEI 不对：在 `CompatibleInfo.cfg` 里找，或用 Frida 抓一次密钥 |
| 8 | 实时读取 | 开始监听后，用另一个号发消息，看「延迟」列 | 数据库太大导致拷贝慢属于 P0 的临时做法，P1 由 wx-agent 在安卓里直接读取 |
| 9 | 界面自动化发送 | 「发送验证」→ 发给 `filehelper` | 调整控件选择器；`am start` 打不开会话时改为搜索联系人 |
| 10 | 相册识别扫码 | 「扫码」→ 上传 → 推送到相册并打开扫一扫 | 用重新生成的清晰二维码；手动在画面里选图 |
| 11 | 虚拟摄像头扫码（可选） | 「扫码」→ 设为摄像头画面 → 在扫一扫里转动视角对准 | 宿主机 v4l2loopback 方案（`webcam0`） |

## 已知限制（只在 P0 存在）

- 数据库验证通过「复制整个数据库再拉取」实现。账号聊天记录多时数据库很大，每次拷贝要好几秒。这只是为了验证密钥和实时性，正式版不会这样读。
- 面板只有中文界面，没有接 Telegram。

## 目录

```
docker/            启动脚本、supervisord 配置、设备配置 (device-env.sh)
manager/app.py     面板主程序：模拟器看门狗、adb root、微信安装、各接口
manager/wxdb.py    数据库解密与实时监听
manager/uiops.py   uiautomator2 界面自动化
manager/scan.py    扫码上传：解码、重新生成、推送相册、虚拟摄像头海报
data/              (运行时) android/ 模拟器磁盘与 device.env、p0/、scan/、logs/
```
